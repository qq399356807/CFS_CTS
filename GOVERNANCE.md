# Project Governance and Originator Intent

## Project scope preserved from the existing project record

FIR is a research program studying relational causal control, higher-order interaction, predictive information, and cross-environment stability. The current repository treats FIR v1.1 as a frozen protocol. Synthetic validation, software tests, and empirical evidence must remain explicitly distinct. Supplementary diagnostics must not silently alter the frozen protocol.

This summary is a concise statement of the scope documented in the repository README and protocol materials. It does not replace or reinterpret the detailed protocol, analysis plan, or historical project records.

## Originator's collaboration intent

The originator's standing instruction for project work is:

- Routine research and maintenance should be handled autonomously by the research assistant: literature and source checks where relevant, reverse validation, analysis, documentation, reproducibility checks, and progress records.
- Do not interrupt the originator for routine progress, ordinary findings, or maintenance decisions that can be handled within the established project scope.
- Contact the originator only when an important matter genuinely requires attention, such as a consequential research decision, evidence that materially challenges a core premise, a substantial change in direction or scope, or explicit approval for a governance-sensitive action.
- Do not make consequential decisions on the originator's behalf. When escalation is necessary, present the evidence, implications, uncertainties, and the specific decision required.
- Preserve the distinction between the originator's stated intent and the assistant's interpretation, operationalization, or proposed improvements. Never present an assistant-authored interpretation as the originator's original statement.
- Do not describe synthetic results, software tests, or simulations as empirical confirmation.
- Make routine documentation and research changes on dedicated branches. Do not merge to `main` without the originator's explicit approval.

## Decision and evidence discipline

1. Preserve the frozen FIR v1.1 protocol unless an explicitly reviewed version change is authorized.
2. Keep protocol changes, analysis changes, and exploratory diagnostics separately identified.
3. Record both supporting and disconfirming results; do not selectively report only favorable outcomes.
4. State the limits of each validation and avoid claims stronger than the evidence.
5. If a proposed change would alter the project's central question, protocol, or interpretation, pause and escalate rather than silently redefining the project.
